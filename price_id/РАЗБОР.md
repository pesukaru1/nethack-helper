# РАЗБОР.md — построчный разбор price_id.py

Этот документ объясняет, как устроен и как работает `price_id.py` (версия 0.4).
Номера строк указаны для версии файла в **1387 строк** (снята 2026-10-03).
Если будешь править код — номера сдвинутся, поэтому в тексте у каждой части
названо имя функции: найти её можно так:

    grep -n "def имя_функции" price_id.py

Как читать: у каждой части сначала идёт цитата кода (иногда сокращённая —
рекомендую смотреть рядом сам файл), затем объяснение — построчно или
по смысловым строкам. В конце — приложения (форматы файлов, откуда взялись
формулы цен, рецепты доработки, словарик Python-приёмов).


## 0. Общая картина

Четыре файла данных, между которыми работает скрипт:

    price_id.html          вики-страница «Price identification» (исходник чисел)
          │  build_data()  — разовый разбор
          ▼
    price_id_data.json     цены: 7 строк свитков и 7 строк зелий (кэш, читается каждый запуск)
          │
    price_id_abbr.json     сокращения предметов (правятся вручную)
          │  lookup()      — поиск по цене
          ▼
    sessions.json          сессии игрока (герой, харизма, предметы)
          │  register_item() / cmd_identify() …
          ▼
    sessions/<имя>/*.csv   таблица «метка → псевдоним → функция» (обновляется на лету)

Поток одной команды `s 30 scroll GHOTI`:

1. `main()` читает аргументы и загружает data.json (или строит его из html).
2. `App.cmd_sell_buy("sell", [...])` парсит ввод: цена 30, вид «свитки», метка GHOTI.
3. `lookup()` проходит по 7 строкам таблицы свитков и собирает все предметы,
   у которых в столбце Selling price встречается 30 (оба числа ячейки: обычное
   и «со скидкой»).
4. `Store.identified_types()` отсеивает уже распознанные типы.
5. `make_alias()` строит псевдоним: ≤5 вариантов — сокращения через `/`,
   ≥6 — `s<цена>_<n>`.
6. Результат печатается; `register_item()` сохраняет запись `GHOTI → bp/ew/ea/rc`
   в sessions.json и перезаписывает CSV сессии.

Четыре команды пользователя и куда они ведут:

| Команда      | Функция            | Что делает                                          |
|--------------|--------------------|-----------------------------------------------------|
| `s`/`b цена` | `cmd_sell_buy`     | поиск по цене, псевдоним, регистрация метки         |
| `i метка X`  | `cmd_identify`     | «распознал»: запись функции, исключение из списков  |
| `n метка X`  | `cmd_name`         | ручная правка псевдонима                            |
| `sess …`     | `cmd_sess`         | сессии: создание, переключение, удаление, `set`     |

Всё остальное — обслуживание: разбор HTML (156–300), файловые утилиты (303–331),
хранилище Store (415–526), логика псевдонимов (585–631), самопроверка (1178–1328).

## 3. cha_bracket — харизма → столбец таблицы: строки 135–149

    def cha_bracket(cha):
        """Ключ столбца таблицы для значения харизмы."""
        if cha <= 5:
            return "le5"        # столбец «Cha ≤ 5»
        if cha <= 7:
            return "6-7"        # столбец «Cha 6–7»
        if cha <= 10:
            return "8-10"
        if cha <= 15:
            return "11-15"
        if cha <= 17:
            return "16-17"
        if cha == 18:
            return "18"
        return "ge19"           # столбец «Cha ≥ 19»

В таблицах вики покупная цена зависит от «коридора» харизмы из семи значений:
≤5, 6–7, 8–10, 11–15, 16–17, 18, ≥19. Функция переводит любое число харизмы
в ключ столбца. Ключи (`"le5"`, `"6-7"`, …) попадают в `price_id_data.json`
на этапе разбора HTML — ровно такие строки-ключи стоят в словаре `buy` каждой
цены-строки. Каскад `if` с возвратами читается сверху вниз: первое сработавшее
условие отдаёт ответ; последний `return` — для всего, что ≥19.

Сравни с `build_data` (строка ~262): оттуда же родом формат ключей — там они
порождаются прямо из заголовков таблицы (`Cha ≤ 5` → `"le5"`).


## 4. Разбор HTML: строки 152–300

Задача этого блока: превратить сохранённую вики-страницу `price_id.html`
в компактную структуру Python. Общая идея — «событийный» разбор
(класс `_TableParser`), затем «сборочная» функция `build_data`.

### 4.1. _TableParser — строки 156–214

Наследник стандартного `HTMLParser`. Особенность этого класса: он не строит
дерево документа, а во время чтения вызывает методы-события, когда встречает
`<тег ...>` (`handle_starttag`), `</тег>` (`handle_endtag`) и текст внутри тегов
(`handle_data`). Наша задача — в этих событиях «собирать» заголовки h2/h3/h4/h5
и таблицы.

    class _TableParser(HTMLParser):
        """Собирает заголовки и таблицы из сохранённой вики-страницы."""

        def __init__(self):                                      # 159
            super().__init__(convert_charrefs=True)              # 160
            self.tables = []                                     # 161
            self.headings = {"h2": "", "h3": "", "h4": "", "h5": ""}   # 162
            self._capture = None     # какой заголовок сейчас читаем     # 163
            self._buf = []           # накопитель текста заголовка       # 164
            self._table = None       # текущая таблица (словарь)         # 165
            self._row = None         # текущая строка таблицы            # 166
            self._cell = None        # текущая ячейка                    # 167
            self._in_caption = False # мы внутри <caption>?               # 168

- 160: `super().__init__(...)` — запуск родительского конструктора; `convert_charrefs=True`
  превращает HTML-сущности (`&amp;`) в символы при чтении текста.
- 161–168: «состояние парсера» — переменные с подчёркиванием — внутренние.
  `in`-префикс подчёркиванием — соглашение: «не трогать снаружи класса».
- Раз `_table` — словарь `{"caption": ..., "rows": [...]}`, парсер наполняет
  его по мере чтения; готовые таблицы складываются в список `self.tables`.

    def handle_starttag(self, tag, attrs):                       # 170
        if tag in ("h2", "h3", "h4", "h5"):                      # 171
            self._capture, self._buf = tag, []                   # 172
        elif tag == "table":                                     # 173
            self._table = {"caption": "", "rows": []}            # 174
        elif tag == "caption" and self._table is not None:       # 175
            self._in_caption, self._buf = True, []               # 176
        elif tag == "tr" and self._table is not None:            # 177
            self._row = []                                       # 178
        elif tag in ("td", "th") and self._row is not None:      # 179
            self._cell = ""                                      # 180
        elif tag == "br" and self._cell is not None:             # 181
            self._cell += " "                                    # 182

- 171–172: встретили новый заголовок — запомнили его тег и начали копить текст.
- 173–174: `<table>` — завели словарь будущей таблицы.
- 175–176: `<caption>` (подпись таблицы «Prices in NetHack 3.6.0 and later»).
- 177–178: `<tr>` — новая строка, ячеек пока нет.
- 179–180: `<td>`/`<th>` — новая ячейка, текст пуст.
- 181–182: `<br>` внутри ячейки — вставляем пробел, чтобы слова не слипались
  («…(20/26)Boot types» → «…(20/26) Boot types»).

    def handle_endtag(self, tag):                                # 184
        if tag in ("h2", "h3", "h4", "h5") and self._capture == tag:   # 185
            self.headings[tag] = " ".join("".join(self._buf).split())  # 186
            for lower in {"h2": ("h3", "h4", "h5"), "h3": ("h4", "h5"),
                          "h4": ("h5",)}.get(tag, ()):                     # 187–188
                self.headings[lower] = ""                          # 189
            self._capture = None                                   # 190
        elif tag == "table" and self._table is not None:           # 191
            path = " > ".join(v for v in (self.headings["h2"], self.headings["h3"],
                                          self.headings["h4"], self.headings["h5"]) if v)  # 192–193
            self._table["path"] = path                             # 194
            self.tables.append(self._table)                        # 195
            self._table = None                                     # 196
        elif tag == "caption" and self._table is not None:         # 197
            self._in_caption = False                               # 198
            self._table["caption"] = " ".join("".join(self._buf).split())  # 199
        elif tag == "tr" and self._row is not None:                # 200
            if self._table is not None:                            # 201
                self._table["rows"].append(self._row)              # 202
            self._row = None                                       # 203
        elif tag in ("td", "th") and self._cell is not None:       # 204
            self._row.append(" ".join(self._cell.split()))         # 205
            self._cell = None                                      # 206

- 186: склеили текст заголовка и нормализовали пробелы
  (`" ".join(text.split())` — приём «сжать все пробелы в один»).
- 187–189: встретился h3 — младшие уровни (h4, h5) сбрасываются, чтобы в `path`
  не попал старый подзаголовок.
- 191–196: `</table>` — таблица готова. Формируем `path` — «хлебные крошки»
  из заголовков: например `Price tables > Scrolls`. Именно по path+подписи
  `build_data` потом найдёт нужные таблицы.
- 199: сохранили подпись таблицы (в неё попадут и слова Expand/Collapse —
  не страшно, важное слово «3.6.0» там есть).
- 200–203: строка закончилась — добавили её в таблицу.
- 204–206: ячейка закончилась — её текст (с сжатыми пробелами) добавили в строку.

    def handle_data(self, data):                                 # 208
        if self._capture is not None:                            # 209
            self._buf.append(data)                               # 210
        if self._in_caption:                                     # 211
            self._buf.append(data)                               # 212
        if self._cell is not None:                               # 213
            self._cell += data                                   # 214

`handle_data` вызывается для любого текста между тегами. Смотрим, «куда» сейчас
идёт чтение: если читаем заголовок — в `_buf`, если подпись таблицы — тоже
в `_buf`, если ячейку — дописываем к строке ячейки.

### 4.2. _cell_numbers — строки 217–219

    def _cell_numbers(text):
        """'120 (160/213)' -> [120, 160, 213]; '30 (23)' -> [30, 23]; '5' -> [5]."""
        return [int(x) for x in re.findall(r"\d+", text)]

Одна строка с регулярным выражением: `re.findall(r"\d+", text)` находит все
последовательности цифр и возвращает их списком строк; генератор списка
`[int(x) for x in ...]` превращает каждую в число. Именно из-за этой функции
в `price_id_data.json` цены лежат списками: покупка — `[120, 160, 213]`
(обычная; с надбавкой; с обеими), продажа — `[30, 23]`.

### 4.3. _parse_items_cell — строки 222–236

    def _parse_items_cell(text):
        """'blank paper ("unlabeled scroll"), enchant weapon' -> список предметов."""
        items = []                                        # 224
        for part in text.split(","):                      # 225
            part = part.strip()                           # 226
            if not part:                                  # 227
                continue                                  # 228
            m = re.match(r'^(.*?)\s*\((.*)\)$', part)     # 229
            if m:                                         # 230
                name = m.group(1).strip()                 # 231
                note = m.group(2).strip().strip('"')      # 232
            else:                                         # 233
                name, note = part, ""                     # 234
            items.append({"name": name, "note": note})    # 235
        return items                                      # 236

Последний столбец таблицы — список предметов с одной ценой, вида
`blank paper ("unlabeled scroll"), enchant weapon`.

- 225: режем по запятой — каждый кусок это один предмет.
- 229: регулярное выражение ищет «имя (пояснение в скобках)». `(.*?)` —
  «нежадная» группа (минимально возможный кусок), `\s*` — пробелы, `\((.*)\)$` —
  скобки до конца строки. Если шаблон совпал, `m.group(1)` — имя, `m.group(2)` —
  пояснение (кавычки срезаем). Не совпал — весь кусок это имя, пояснения нет.
- 235: результат — словарь с ключами `name` и `note`; в `note` попадает
  в т.ч. `unlabeled scroll` у blank paper и `blessed clear potion` у holy water.

### 8.3. sucker_sell_rows — строки 571–582

    def sucker_sell_rows(data, kind, price):
        """Строки, у которых цена продажи «сучку» (base/3, округл.) равна price.
        Только для подсказки, когда обычный поиск ничего не нашёл."""
        out = []
        for row in data["classes"][kind]["rows"]:
            base = row["base"]
            t = 5 if base == 0 else base
            t = (t * 10) // 3                 # умножить на 10, разделить на 3 —
            t = (t + 5) // 10                 # так же округляет сам NetHack
            if t == price and base != 0:
                out.append(row)
        return out

Если при продаже цена не нашлась нигде, возможно, персонаж — «сучок» (dunce

цены** вместо половины. Формула `(t*10)//3` затем `(t+5)//10` — это в точности
округление из исходников NetHack (`shk.c`, функция `set_cost`): «умножить на 10,
поделить, прибавить 5, поделить на 10» — округление до ближайшего целого.
Строка с базой 0 (бесполезная вода) пропускается — она и так стоит ноль.

### 8.5. next_s_index — строки 634–641

    def next_s_index(sess, prefix):

        n = 0

Ищет среди псевдонимов сессии все `s<цена>_<номер>` с нужным префиксом
(например, `s75_`) и возвращает **максимальный номер + 1**. Регулярка
`^s(\d+)_(\d+)$` — «строка целиком состоит из s, цифр, подчёркивания, цифр»;
скобки `(\d+)` это «группы», их потом читаем через `m.group(1)`/`m.group(2)`.
«Максимум + 1», а не «количество + 1» — чтобы удаление старого псевдонима
не приводило к повторному использованию номера.

# Приложение A. Форматы данных

### price_id_data.json (фрагмент)

    {
     "format": "nethack-price-id",
     "format_version": 1,
     "generated_at": "…",
     "source": "price_id.html",
     "classes": {
      "scrolls": {
       "rows": [
        {"base": 20,
         "buy": {"le5": [40, 53, 71], "6-7": [30, 40, 53], "8-10": [27, 36, 47],
                 "11-15": [20, 27, 36], "16-17": [15, 20, 27], "18": [13, 18, 24],
                 "ge19": [10, 13, 18]},
         "sell": [10, 8],
         "items": [{"name": "identify", "note": ""}]},
        …
       ]},
      "potions": { … }
     },
     "labels": {"scrolls": [ … 41 метка … ], "potions": [ … 25 цветов … ]},
     "abbr_defaults": { … справочная копия встроенных сокращений … }
    }

Как читать: `buy[ключ]` — три числа покупки для коридора харизмы
(обычная / +1/3 / +2/3-итого), `sell` — два числа продажи (обычная / со скидкой),
`items` — какие типы предметов имеют эту цену.

### sessions.json (пример из рабочей сессии)

    {
     "format": "nethack-price-id-sessions",
     "format_version": 1,
     "last": "honor_yeno",
     "sessions": {
      "honor_yeno": {
       "dir": "honor_yeno", "hero": "yeno", "role": "", "cha": 10,
       "extra": {}, "items": [
        {"kind": "scrolls", "label": "GHOTI", "alias": "bp/ew/ea/rc",
         "identified_as": null,
         "price": {"mode": "sell", "value": 30},
         "candidates": ["blank paper", "enchant weapon", "enchant armor", "remove curse"],
         "updated": "2026-10-03 19:05"}
       ],
       "created": "2026-10-03 18:19"
      }
     }
    }

`last` — сессия по умолчанию; `dir` — имя папки CSV; `items` — записи предметов;
`extra` — пользовательские характеристики (`sess set …`).

### sessions/<имя>/scrolls.csv

    appearance;alias;function
    GHOTI;bp/ew/ea/rc;
    TEMOV;blank/enchw/enchar/remcur;
    KIRJE;bpap/enweap/earm/rcur;scroll of enchant armor

Колонка `function` заполняется, когда предмет распознан (`i метка предмет`).
Файл перезаписывается при каждом изменении — его всегда можно смотреть
в Excel/Sheets (разделитель `;` выбран под русскую локаль).


# Приложение B. Откуда взялись числа в таблицах

Числа не «придуманы скриптом» — они взяты из вики-страницы «Price
identification» (файл `price_id.html`) и перепроверены по исходникам
NetHack 3.6.6 (`shk.c`, функции `get_cost` и `set_cost`):

* **Покупка**: цена = базовая × множитель харизмы (≤5 — ×2; 6–7 — ×3/2;
  8–10 — ×4/3; 11–15 — ×1; 16–17 — ×3/4; 18 — ×2/3; ≥19 — ×1/2), округление —
  «умножить на 10, поделить, +5, поделить на 10». Три числа в ячейке:
  без надбавок; с +1/3 (это либо неопознанный предмет, либо персонаж-«сучок»:
  dunce cap / видимая рубашка / Tourist < 15 ур.); с обеими надбавками.
* **Продажа**: цена = базовая / 2 (или / 3 у «сучка»), а у «жадного» магазина
  (каждый четвёртый) — минус четверть. Два числа в ячейке: обычное / со скидкой.
  Комбинации «сучок+жадный» в таблице нет — поэтому для них есть подсказка
  `sucker_sell_rows` при нулевом результате.
* Почему можно «отбрасывать распознанные»: в партии метка свитка связана
  с типом **взаимно-однозначно** (21 тип получает 21 различную метку из пула
  в 41; шуффл — `o_init.c`, `shuffle_all`). Значит, если метка GHOTI — это
  enchant weapon (распознан), то другая метка уже не может быть enchant weapon.
  Аналогично цвета зелий. На этом свойстве держится команда `i`.

Проверка формул сделана программно: все ячейки таблиц 3.6.0+ для свитков
и зелий пересчитываются этими формулами до последней цифры (единственное
исключение — строка «mummy wrapping» в броне, вики считает её по своим правилам;
к свиткам/зельям отношения не имеет).
